# 고교나침반 하네스 — 파이프라인 (harness-pipeline.md)

> 기준 문서: docs/harness-purpose.md (입력·완료 기준), docs/story-work.md (손 작업 7단계)

## 1. 단계 (5개)

| 단계 | 묶은 손 작업 | 입력 | 출력 | 도구 |
|---|---|---|---|---|
| S1 리서치 | 1 레퍼런스 수집, 2 분석 | 선택한 화면 2~3개 | 레퍼런스 목록 + 화면별 가져올 것/버릴 것 | uibowl |
| S2 설계 | 3 화면 설계 문서 | S1 출력, story-service, school-design | 화면별 설계 문서 | — |
| S3 시안 | 4 키스크린, 6 토큰·컴포넌트 적용 | S2 출력, school-design | 390×844 HTML 시안 (화면당 1개) | — |
| S4 판정 | 7 가이드 검토 | S3 출력, 규칙 파일 | 위반 목록 (0건이면 통과) | 판정 스크립트 |
| S5 공유 | 5 공유 URL 정리 | S4 통과 시안 | 시안별 공유 URL 목록 | — |

## 2. 순서 원칙
- 손 작업은 공유(5) → 수정(6) → 검토(7) 순서였지만, 하네스는 판정(S4) 후 공유(S5) 순서로 바꾼다
- 이유: 완료 기준이 "위반 0건 + 공유 URL 목록"이므로, 통과한 시안만 공유한다

## 3. 되돌아가는 지점
| 조건 | 복귀 | 최대 횟수 | 초과 시 |
|---|---|---|---|
| S4 위반 1건 이상 | S3 시안으로 | 2회 (손 작업의 1·2차 수정) | 3회째 실패하면 멈추고 위반 목록을 보고 |

- 복귀할 때는 위반 목록 파일을 S3의 입력으로 함께 넘긴다
- 재시도 횟수는 파일에 기록해 셀 수 있게 한다 (R4에서 파일명 확정)

## 4. 공유 URL 규칙 (S5)
- 하네스는 URL 목록만 만들고, 업로드(push)와 메일 전송은 본인이 한다
- 형식: 정적 호스팅 주소 규칙 (예: GitHub Pages `…/drafts/<화면명>.html`)
- 목록 한 줄 = 시안 하나: `시안 A — <URL>`

## 5. 파이프라인 밖 (선택 단계)
- 피그마 전송: S5 이후 별도로 요청할 때만 실행
