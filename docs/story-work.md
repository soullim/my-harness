# 고교나침반 — 작업 흐름 (story-work.md)

> 이 문서는 "실제로 어떻게 작업했는지"만 기록한다.
> 서비스가 무엇을 위한 것인지는 docs/story-service.md를 기준으로 한다.
> 개인 프로젝트이므로 수정 요청과 검토는 모두 본인이 한다.

## 작업 흐름 (7단계)
1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다
2. 나는 레퍼런스를 분석하고 우리 서비스에 반영할 부분을 추린다
3. 나는 분석 내용을 토대로 화면 설계 문서를 구체화한다
4. 나는 피그마에서 레퍼런스와 화면 설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다
5. 나는 시안을 프로토타입으로 시안별 정리하고, 공유 URL을 메일로 보내 컨셉시안을 공유한다
6. 나는 1·2차 수정을 거친 뒤 최종 시안을 기반으로 디자인 토큰과 컴포넌트를 만들고 화면 디자인에 들어간다
7. 나는 완성된 시안의 토큰·컴포넌트가 우리 가이드를 위반한 부분이 없는지 검토한다

## 산출물 · 멈칫 · 넘김

| # | 명사 (산출물) | 멈칫 (게이트 위치) | 넘김 (에이전트 경계) |
|---|---|---|---|
| 1 | 경쟁사 레퍼런스 모음 | 없음 | 나 → uibowl (도구) |
| 2 | 레퍼런스 분석 노트, 우리 서비스 반영 포인트 | 없음 | 없음 |
| 3 | 화면 설계 문서 | 없음 | 없음 |
| 4 | UI 키스크린 2~3개 (390×844) | 없음 | 나 → 피그마 (도구) |
| 5 | 컨셉시안 프로토타입 (시안별 정리본), 공유 URL | 없음 | 나 → 메일 수신자 (공유 URL 전달) |
| 6 | 1·2차 수정본, 최종 시안, 디자인 토큰, 컴포넌트, 화면 디자인 | 없음 | 없음 (수정 요청도 본인) |
| 7 | 가이드 검토 결과 (위반 항목 목록) | 없음 | 없음 (검토도 본인) |

## 5단계 공유 방식 메모
- 공유받는 사람에게는 프로토타입 공유 URL을 메일로 보낸다
- 5단계 결과물은 시안별 공유 URL만 추출한 형식이면 충분하다 (예: 시안 A — URL / 시안 B — URL)
